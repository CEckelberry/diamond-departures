# Packet P0-03-RED — MLB Mock Tests (TDD)

## 1. Concise Plan

1.  **Analyze Requirements**: Based on standard MLB AMI (Amateur/Minor/MLB) API structures and the scope defined, we need to mock four specific endpoints.
2.  **Define Contracts**:
    *   `GET /api/v1/schedule?date=today`: Returns a list of games for the specified date.
    *   `GET /api/v1/game/{id}/feed/live`: Returns live game data (score, inning, status).
    *   `GET /api/v1/people/{id}/stats?group=hitting,pitching`: Returns player statistics filtered by group.
    *   `GET /api/v1/teams/{id}/roster`: Returns the current roster for a team.
3.  **Create Test Structure**:
    *   `tests/mlb_mock/test_contracts.py`: Contains `unittest.TestCase` classes for each endpoint.
    *   `tests/mlb_mock/fixtures/`: JSON files representing expected responses for validation.
    *   `tests/mlb_mock/README.md`: Documents assumptions (e.g., "today" maps to a fixed date for determinism).
4.  **Implement Tests**: Write tests that assert HTTP status codes, JSON schema keys, and data types. These will initially fail because the mock service at `localhost:8090` does not exist yet.
5.  **Verify RED State**: Run the tests to confirm they fail as expected.

# Packet P7-05 — Implementation Plan & Diff

## 1. Plan, Assumptions & Risks

### Assumptions
1.  **Framework**: The project uses **Next.js (App Router)** with **TypeScript**. This is the standard for modern "implementation-ready" web tasks unless specified otherwise.
2.  **Styling**: Tailwind CSS is available and configured.
3.  **Structure**: The project follows a standard Next.js directory structure (`app/`, `components/`, `lib/`).
4.  **Content**: The methodology content is static for this scope (no CMS integration yet), but structured as a reusable component.
5.  **Footer**: A `Footer` component exists in `components/ui/footer.tsx` (or similar). If it doesn't exist, we will create a minimal one to ensure the link requirement is met without breaking existing builds.

### Risks & Mitigations
1.  **Risk**: `Footer` component does not exist.
    *   *Mitigation*: Create a robust `Footer` component in `components/ui/footer.tsx` that includes standard links and the new Methodology link.
2.  **Risk**: Route conflict if `/methodology` already exists.
    *   *Mitigation*: The diff will create the directory structure. If it exists, the user should merge. We assume it does not exist per "Add `/methodology` page route".
3.  **Risk**: SEO/Meta tags missing.
    *   *Mitigation*: Include proper `metadata` export in the page file.
4.  **Risk**: Accessibility (a11y) issues.
    *   *Mitigation*: Use semantic HTML (`<article>`, `<section>`, `<h1>`-`<h3>`) and ensure sufficient contrast in Tailwind classes.

### Edge Cases
-   **Mobile Responsiveness**: The methodology page should be readable on mobile. We'll use a max-width container with responsive padding.
-   **Link Targets**: Links to GitHub/Docs should open in new tabs (`target="_blank" rel="noopener noreferrer"`).

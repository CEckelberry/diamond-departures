### Risks & Edge Cases
1. **Race condition**: If reconciliation sweep takes too long, it might delay the next incremental scan
2. **Memory leak**: Storing reconciliation results could grow unbounded if not cleaned up
3. **State inconsistency**: If reconciliation fails mid-way, the system might be in an inconsistent state
4. **Performance impact**: Full live sweeps are expensive - need to ensure they don't overwhelm the system
5. **Configuration drift**: If `RECONCILE_EVERY_N_SCANS` is set too low, it could cause excessive full scans

### Implementation Strategy
1. Add configuration parameter `RECONCILE_EVERY_N_SCANS`
2. Modify checkpoint to include `scan_count`
3. Add reconciliation trigger logic every N scans
4. Emit new telemetry fields in job output
5. Add tests for the new functionality

Here is the implementation plan and code changes for **Packet P6-03**.

### 1. Plan & Assumptions

**Assumptions:**
1.  **Backend API Contract:** The `/api/season-state` endpoint returns a JSON object with the following structure (based on Task 6.3 spec):
    ```json
    {
      "mode": "between", // or "off-game", "live", "off-season"
      "games_in_progress": 0,
      "next_game_at": "2023-10-27T19:00:00Z", // ISO string, null if no games today
      "updated_at": "..."
    }
    ```
2.  **SSE Reconnection:** The `openBoardStream` function currently uses exponential backoff. We need to expose a way to configure the *initial* delay or the *max* delay for idle states to satisfy the "slower heartbeat" requirement.
3.  **State Management:** The `Header.svelte` is the source of truth for the UI banner. The `+page.svelte` needs to listen to this state to adjust the SSE connection parameters (specifically the reconnect strategy).

**Risks & Edge Cases:**
1.  **Timezone Handling:** `next_game_at` is likely UTC. The banner must display local time.
2.  **Stale Data:** If the user sits on the page for hours during "no games", the `next_game_at` might become invalid (e.g., game started 5 mins ago but API hasn't updated). The SSE connection *must* remain active to catch the transition to `live`.
3.  **SSE "Heartbeat" vs "Reconnect":** The spec asks for a "slower heartbeat". In SSE, this usually means the server sends a comment every X seconds, or the client reconnects less aggressively. Since we control the client, we will implement a **longer initial reconnect delay** for idle states to reduce server load and noise.
4.  **Race Conditions:** If `seasonState` updates from `live` to `between` while the SSE stream is active, we need to ensure the stream doesn't drop unnecessarily.

**Implementation Steps:**
1.  **Update `Header.svelte`:**
    *   Add logic to calculate "Next Game ETA" (Hours/Minutes).
    *   Render the specific banner text: "No games until [Time] · in [N hours]".
    *   Expose the `seasonState` via a Svelte store or prop so `+page.svelte` can react to it.
2.  **Update `+page.svelte`:**
    *   Import the season state logic (or lift it up).
    *   Pass a `reconnectStrategy` to `openBoardStream`.
    *   If `mode` is `between` or `off-game`, use a slower reconnect policy (e.g., 2-minute initial delay, capped at 5 mins).
3.  **Update `openBoardStream`:**
    *   Accept an optional `reconnectDelay` configuration object.

#### File: `src/lib/stores/season.ts` (New File)
*Change:* Centralize season state logic to share between Header and Page.

```typescript
import { writable } from 'svelte/store';

export type SeasonMode = 'live' | 'between' | 'off-game' | 'off-season';

export interface SeasonState {
	mode: SeasonMode;
	gamesInProgress: number;
	nextGameAt: string | null;
	updatedAt: string | null;
}

const initialState: SeasonState = {
	mode: 'off-season',
	gamesInProgress: 0,
	nextGameAt: null,
	updatedAt: null
};

export const seasonState = writable<SeasonState>(initialState);

export async function fetchSeasonState() {
	try {
		const res = await fetch('/api/season-state');
		if (!res.ok) return;
		const data = await res.json();
		
		seasonState.set({
			mode: data.mode ?? 'off-season',
			gamesInProgress: Number(data.games_in_progress ?? 0),
			nextGameAt: typeof data.next_game_at === 'string' ? data.next_game_at : null,
			updatedAt: data.updated_at ?? null
		});
	} catch (e) {
		console.error('Failed to fetch season state', e);
	}
}
```

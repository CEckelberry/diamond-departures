# Packet P7-02-RED — Accessibility Pass Tests First

## 1. Plan

### Assumptions
1.  **Framework**: The project uses **Jest** for unit testing and **React Testing Library (RTL)** for component interaction testing.
2.  **Component Structure**: There is a `Board` component that renders a grid of `Panel` components. `Panel` likely handles click/hover states and exposes keyboard navigation.
3.  **State Management**: Board state (selected panel, open flap/panel details) is managed within `Board` or a context, but for these tests, we will assume standard prop drilling or RTL queries are sufficient to verify DOM state.
4.  **Existing Codebase**: The `Row interactions` mentioned in the scope imply that keyboard navigation currently lacks proper ARIA labels or announcement logic, which we are explicitly testing against to ensure they fail (RED).

### Risks & Edge Cases
1.  **Flaky DOM Queries**: Relying on specific `id` attributes that might change. *Mitigation*: Use semantic queries (`getByRole`, `getByText`) and `data-testid` only as fallbacks.
2.  **Async Announcements**: Screen reader announcements (polite) are often asynchronous or debounced. *Mitigation*: Use `waitFor` to ensure the announcement has been added to the DOM before asserting.
3.  **Focus Management**: Keyboard focus might not move immediately after an action. *Mitigation*: Explicitly await focus changes or use RTL's built-in focus tracking.
4.  **Esc Key Behavior**: The `Escape` key might be handled by a parent modal or the browser. *Mitigation*: Ensure the test environment simulates the keydown event on the correct target (the focused panel or board).

### Implementation Strategy
1.  Create `Board.a11y.test.js`.
2.  **Test 1: Keyboard Row Focus/Activation**: Verify that arrow keys move focus between panels and that Enter/Space activates them. Assert that the `aria-pressed` or `aria-selected` state updates correctly.
3.  **Test 2: Esc-Close Behavior**: Open a panel/flap, then press Escape. Assert that the panel closes and focus returns to the triggering element.
4.  **Test 3: ARIA Labels**: Verify that each panel has a descriptive `aria-label` based on its content (e.g., "Panel 1, Row 1").
5.  **Test 4: Polite Announcement**: Trigger an action and verify that a live region (e.g., `<div aria-live="polite">`) contains the expected announcement text after a short delay.
6.  **Test 5: Regression Warning**: Intentionally test for a known missing ARIA attribute or incorrect role in the current `Row` implementation to ensure it fails.

import React from 'react';
import { render, screen, fireEvent, waitFor } from '@testing-library/react';
import Board from './Board';

// Mock data for consistent testing
const mockData = [
  { id: 'row-1', panels: [{ id: 'p-1', label: 'Panel 1' }, { id: 'p-2', label: 'Panel 2' }] },
  { id: 'row-2', panels: [{ id: 'p-3', label: 'Panel 3' }, { id: 'p-4', label: 'Panel 4' }] },
];

describe('Board Accessibility Contract Tests', () => {
  beforeEach(() => {
    render(<Board data={mockData} />);
  });

  describe('Keyboard Navigation & Activation', () => {
    it('should move focus between panels using arrow keys', () => {
      const firstPanel = screen.getByRole('button', { name: /panel 1/i });
      
      // Focus the first panel
      fireEvent.focus(firstPanel);
      expect(document.activeElement).toBe(firstPanel);

      // Simulate ArrowRight key
      fireEvent.keyDown(firstPanel, { key: 'ArrowRight', code: 'ArrowRight' });

      // The second panel should now be focused
      const secondPanel = screen.getByRole('button', { name: /panel 2/i });
      expect(document.activeElement).toBe(secondPanel);
    });

    it('should activate a panel when Enter is pressed', () => {
      const panel = screen.getByRole('button', { name: /panel 1/i });
      
      fireEvent.click(panel); // Simulate initial focus/click to open state if needed
      // Assuming activation toggles a class or state
      // For this test, we verify the aria-pressed attribute updates if it's a toggle
      // If it's just selection, we check aria-selected
      
      // Note: This test assumes the component uses aria-pressed for selection state
      // Adjust based on actual implementation
      fireEvent.keyDown(panel, { key: 'Enter', code: 'Enter' });
      
      // Verify some visual or ARIA change indicating activation
      // For example, if activation adds a class or changes aria-pressed
      expect(panel).toHaveAttribute('aria-pressed', 'true');
    });
  });

  describe('Escape Key Behavior', () => {
    it('should close the open panel when Escape is pressed', async () => {
      const panel = screen.getByRole('button', { name: /panel 1/i });
      
      // Open the panel
      fireEvent.click(panel);
      
      // Verify panel is open (assuming a modal or expanded view is rendered)
      // This depends on how 'open' is represented in the DOM.
      // Let's assume an expanded panel has a specific role or text
      const expandedPanel = await screen.findByRole('dialog', { name: /panel 1/i });
      expect(expandedPanel).toBeInTheDocument();

      // Press Escape
      fireEvent.keyDown(document.activeElement, { key: 'Escape', code: 'Escape' });

      // Verify panel is closed
      await waitFor(() => {
        expect(screen.queryByRole('dialog', { name: /panel 1/i })).not.toBeInTheDocument();
      });
    });
  });

  describe('ARIA Labels', () => {
    it('should provide descriptive aria-labels for each panel', () => {
      mockData.forEach((row) => {
        row.panels.forEach((panel) => {
          const element = screen.getByRole('button', { name: new RegExp(panel.label, 'i') });
          expect(element).toHaveAttribute('aria-label', panel.label);
        });
      });
    });
  });

  describe('Polite Announcements', () => {
    it('should announce panel activation to screen readers', async () => {
      const panel = screen.getByRole('button', { name: /panel 1/i });
      
      // Ensure there is a live region for announcements
      const liveRegion = screen.getByRole('status'); // or query by aria-live="polite"
      expect(liveRegion).toBeInTheDocument();

      // Activate the panel
      fireEvent.click(panel);

      // Wait for the announcement to appear
      await waitFor(() => {
        expect(liveRegion).toHaveTextContent(/panel 1 activated/i);
      });
    });
  });

  describe('Regression Warnings', () => {
    it('should fail if Row components lack required aria attributes', () => {
      // This test is designed to FAIL if the bug is fixed.
      // It checks for a known missing attribute in the current implementation.
      // For example, if rows are not marked as 'rowgroup' or panels lack tabindex
      const allPanels = screen.getAllByRole('button');
      
      // Check if all panels have tabindex="0" (or similar)
      allPanels.forEach((panel) => {
        expect(panel).toHaveAttribute('tabindex', '0');
      });
    });
  });
});

# Packet P7-02 — Accessibility Pass GREEN

## 1. Plan

### Assumptions
1.  **Framework**: Svelte 3/4 with TypeScript.
2.  **Component Structure**:
    *   `Row.svelte`: Represents a list item (e.g., song, playlist, artist).
    *   `PlayerDetail.svelte` (or similar): A modal/drawer component displaying details about the selected item.
    *   `Flap.svelte` (or similar): A collapsible section or card component within rows.
3.  **State Management**: Global store (`appStore` or `playerStore`) manages the currently selected item and the visibility of the detail panel.
4.  **Testing**: Vitest + Testing Library is used. `svelte-check` is configured for accessibility rules (likely `eslint-plugin-jsx-a11y` or Svelte-specific a11y checks).

### Risks & Failure Modes
1.  **Focus Trap**: Closing the detail panel with `Esc` must return focus to the element that opened it. *Mitigation*: Store `triggerElement` in the store or component state.
2.  **Screen Reader Announcements**: Changing the selected item via keyboard must announce the new selection. *Mituation*: Use `aria-live="polite"` region or explicit `role="status"` updates.
3.  **Event Bubbling**: `Enter`/`Space` on nested interactive elements (e.g., buttons inside a row) should not trigger the row activation. *Mitigation*: Check `event.target` or use `stopPropagation` on inner buttons.
4.  **Svelte-Check False Positives**: Removing `tabindex="0"` might break custom keyboard handling if not replaced with `<button>` or proper `role="button"`. *Mitigation*: Ensure semantic HTML or explicit `role` and `tabindex` are used correctly.

### Implementation Strategy
1.  **Row Component**:
    *   Replace `<div>` with `<button>` or add `role="button" tabindex="0"` if `<button>` is not feasible due to layout.
    *   Add `keydown` handler for `Enter` and `Space`.
    *   Ensure `aria-pressed` or `aria-selected` reflects state.
2.  **Player Detail Panel**:
    *   Add `keydown` listener for `Escape` to close.
    *   Implement focus restoration logic.
3.  **Flap/Row Labels**:
    *   Add `aria-label` or `aria-labelledby` to flaps/rows for screen readers.
    *   Add `aria-live` region for dynamic announcements (e.g., "Song X selected").
4.  **Cleanup**:
    *   Remove any `<!-- svelte-ignore a11y ... -->` comments that are no longer needed.
    *   Verify `svelte-check` passes.

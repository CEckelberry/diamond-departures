# Packet P7-02 — Accessibility Pass GREEN

## 1. Plan

### Assumptions
1.  **Framework**: Svelte 4+ (standard component lifecycle).
2.  **Styling**: CSS classes are present but may lack semantic hooks. We will add `role` and `tabindex` attributes directly to elements where CSS classes alone are insufficient for screen readers.
3.  **State Management**: A global or parent-level store/event bus exists for the "Player Detail Panel" state. We will assume a simple event-based or store-based approach for closing the panel.
4.  **Existing Code**: There are existing `Row` components and a `PlayerDetailPanel` component that currently lack proper keyboard interaction or ARIA labels.

### Risks & Failure Modes
1.  **Focus Trap**: If the Player Detail Panel opens, focus must move into it. If it closes, focus must return to the trigger element. *Mitigation*: Implement basic focus management logic in the panel component.
2.  **Double Activation**: `click` and `Enter`/`Space` might trigger duplicate actions if not handled carefully. *Mitigation*: Use a single handler bound to both events, or rely on native `<button>` semantics where possible.
3.  **Svelte-Check False Positives**: Removing warnings requires ensuring that `aria-*` attributes are correctly typed and used. *Mitigation*: Explicitly add `role`, `aria-label`, and `aria-expanded` where needed.
4.  **Event Propagation**: `keydown` events on rows might bubble up unexpectedly. *Mitigation*: Use `on:keydown` with specific key checks.

### Implementation Strategy
1.  **Row Component (`src/lib/components/Row.svelte`)**:
    *   Convert the interactive wrapper to a `<button>` or add `role="button"` and `tabindex="0"`.
    *   Add `on:keydown` handler for `Enter` and `Space`.
    *   Add `aria-label` based on props.
2.  **Player Detail Panel (`src/lib/components/PlayerDetailPanel.svelte`)**:
    *   Add `role="dialog"` and `aria-modal="true"`.
    *   Add `on:keydown` listener for `Escape` to close the panel.
    *   Ensure focus is managed (move to panel on open, return on close).
3.  **Announcements**:
    *   Use a live region (`aria-live="polite"`) to announce row selections or panel openings if not handled by native UI semantics.

    - Navigate to the player list using `Tab`.
    - Verify that each row is focusable and highlighted.
    - Press `Enter` or `Space` on a row.
    - Verify that the Player Detail Panel opens.
    - Verify that focus is moved into the panel (e.g., to the close button or first interactive element).

    - Verify that the panel closes and focus returns to the previously focused row.

    - Use NVDA (Windows) or VoiceOver (Mac).
    - Navigate to the player list.
    - Verify that each row is announced as a "button" with the correct label.
    - Open the panel and verify it is announced as a "dialog".
    - Close the panel and verify focus return.

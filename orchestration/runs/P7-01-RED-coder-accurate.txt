# Packet P7-01-RED — Performance pass tests first

## 1. Plan

### Assumptions
1.  **Framework**: React 18+ with `react-test-renderer` or `@testing-library/react`.
2.  **State Management**: Redux or Context API used for board state (sort/view toggles).
3.  **Animation**: CSS transitions/animations handled via a library like `framer-motion` or standard CSS classes triggered by state.
4.  **Network**: Mocking is done via `msw` or native `fetch`/`XMLHttpRequest` stubs.
5.  **Performance Metrics**: We will measure React renders (via `useEffect` counters) and network requests (via mock handlers).

### Risks & Edge Cases
1.  **Flakiness**: Performance tests can be flaky if they rely on wall-clock time. *Mitigation*: Use logical counts (render calls, network requests) rather than `setTimeout` delays where possible.
2.  **Over-Mocking**: Mocking too much of the rendering pipeline can hide real performance issues. *Mitigation*: Only mock network and external side-effects; let React render internally.
3.  **Reduced Motion Detection**: Browser APIs like `matchMedia` may not be fully polyfilled in JSDOM. *Mitigation*: Explicitly mock `window.matchMedia`.

### Implementation Strategy
1.  **Test 1: No Unnecessary Re-streams**.
    *   *Scenario*: User toggles sort order or view mode (e.g., Grid/List).
    *   *Check*: Verify that no new WebSocket connection or HTTP fetch for "stream" data occurs. Only local state updates should happen.
2.  **Test 2: Lightweight Board Render**.
    *   *Scenario*: Apply a delta update to the board (e.g., one card moves).
    *   *Check*: Verify that the component does not re-seed the entire dataset. We’ll track the number of times the "seed" function is called vs. "update" function.
3.  **Test 3: Reduced Motion**.
    *   *Scenario*: User has `prefers-reduced-motion: reduce` set.
    *   *Check*: Verify that animation props/hooks do not trigger complex animations or that CSS classes for animations are not applied.
4.  **Benchmark Script**:
    *   A simple Node.js script that runs the tests and outputs a summary, ensuring reproducibility.

### File: `src/hooks/useReducedMotion.ts`
*New hook for reduced motion detection.*

```tsx
import { useEffect, useState } from 'react';

export const useReducedMotion = (): boolean => {
  const [prefersReducedMotion, setPrefersReducedMotion] = useState(false);

  useEffect(() => {
    const mediaQuery = window.matchMedia('(prefers-reduced-motion: reduce)');
    const handleChange = (e: MediaQueryListEvent) => {
      setPrefersReducedMotion(e.matches);
    };

    setPrefersReducedMotion(mediaQuery.matches);
    mediaQuery.addEventListener('change', handleChange);

    return () => {
      mediaQuery.removeEventListener('change', handleChange);
    };
  }, []);

  return prefersReducedMotion;
};
```

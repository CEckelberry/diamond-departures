# Packet P6-03-RED — Implementation Plan & Code

## 1. Plan, Assumptions, and Risks

### Assumptions
1.  **Architecture**: The frontend uses a React-based architecture with a custom `useSSE` hook for server-sent events and a `Header` component that displays game status.
2.  **State Management**: Game state is derived from a store (e.g., Redux/Zustand) exposing `isOffSeason`, `nextGameTime`, and `currentGameState`.
3.  **SSE Contract**: The SSE connection is expected to remain open during "between games" or "no games today" states, but the heartbeat interval should be reduced (slower) compared to active game states to save resources.
4.  **Sorting**: The stat picker component relies on a sorting utility that must remain functional regardless of game state.

### Risks & Failure Modes
1.  **SSE Connection Drop**: If the backend closes the SSE connection during idle states, the frontend will fail to reconnect or show stale data. *Mitigation*: Test the `onclose` and `reconnect` logic explicitly for idle states.
2.  **Header Copy Ambiguity**: "No Games Today" vs. "Between Games" might look similar to users if not distinct. *Mitigation*: Ensure exact string matching in tests.
3.  **Heartbeat Timing Drift**: If the "slower" heartbeat is implemented as a simple timeout without proper cleanup, it may leak timers or cause race conditions during state transitions. *Mitigation*: Verify `useEffect` cleanup functions.
4.  **Stat Picker Sorting Regression**: Changes to game state logic might inadvertently affect the sorting algorithm's stability. *Mitigation*: Isolate sorting tests from game state mocks.

### Edge Cases
-   **Transition from Active Game to Idle**: Ensure SSE doesn't drop abruptly.
-   **No Games Today vs. Off-Season**: The header copy must differ (Off-season implies long break; No Games Today implies short break).
-   **Timezone Changes**: If the user changes timezone during "No Games Today", does the state update correctly? (Out of scope for this packet, but noted).

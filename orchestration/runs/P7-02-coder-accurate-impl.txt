## 1. Plan

### Assumptions
1.  **Framework**: Svelte 3/4 with TypeScript.
2.  **Component Structure**:
    *   `Row.svelte`: Represents a list item (e.g., song, track, or menu item). It currently likely uses a `<div>` or lacks explicit role/keyboard handlers.
    *   `PlayerDetail.svelte` (or similar): A modal/drawer component showing details about the currently selected item.
3.  **State Management**: Global store (`appStore` or `playerStore`) manages the `selectedItem` and `isPlayerOpen` state.
4.  **Testing**: Vitest + Testing Library is used for unit tests.

### Risks & Failure Modes
1.  **Double Activation**: Pressing Enter on a focused row might trigger both the native click event (if bound) and a custom handler. *Mitigation*: Use `on:keydown` specifically for Enter/Space and ensure `on:click` doesn't duplicate logic, or rely on `<button>` semantics if appropriate. However, for list rows, explicit keyboard handling on `<div>` is often preferred to maintain visual styling flexibility while ensuring accessibility.
2.  **Focus Trap**: When `PlayerDetail` opens, focus should ideally move into the panel. *Mitigation*: Use `svelte:after` or a `use:action` to manage focus, but for this baseline, we ensure `Esc` closes it and focus returns to the trigger if possible, or at least doesn't get lost.
3.  **Screen Reader Announcements**: Changing `selectedItem` might not announce the change. *Mitigation*: Use an aria-live region or explicit announcement logic if required by the scope. The scope mentions "announcement behavior," so we will add a live region for selection changes.
4.  **Svelte-check Warnings**: Existing warnings might be due to missing `role`, `tabindex`, or `aria-*` attributes on interactive elements. *Mitigation*: Add explicit `role="button"` (if using div) and `tabindex="0"`, or better, use `<button>` if the row is purely interactive. Given "row interactions," we'll assume a custom component where we add proper ARIA roles.

### Implementation Strategy
1.  **`Row.svelte`**:
    *   Add `role="button"` and `tabindex="0"` to the root element.
    *   Add `on:keydown` handler for `Enter` and `Space`.
    *   Prevent default behavior for Space to avoid scrolling.
    *   Ensure `aria-pressed` or similar state is reflected if applicable (or just `aria-selected`).
2.  **`PlayerDetail.svelte`**:
    *   Add `on:keydown` listener on the overlay/root to catch `Escape`.
    *   Call `close()` or set `isOpen = false` on Escape.
3.  **Announcement Logic**:
    *   Create a small utility or component snippet for aria-live announcements when selection changes.
4.  **Tests**:
    *   Verify keyboard activation of Row.
    *   Verify Esc closes PlayerDetail.
    *   Verify no svelte-check warnings.

### File: `src/lib/utils/a11y.ts` (New File)

```typescript
export function announce(message: string) {
  const liveRegion = document.getElementById('aria-live-region');
  if (!liveRegion) return;
  
  // Clear and set to ensure screen readers pick up the change
  liveRegion.textContent = '';
  setTimeout(() => {
    liveRegion.textContent = message;
  }, 100);
}
```

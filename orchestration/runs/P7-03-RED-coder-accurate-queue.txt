# Packet P7-03-RED — Mobile Experience Tests

## 1. Plan

### Assumptions
1.  **Framework**: The project uses **React** with **Jest** and **Testing Library** (`@testing-library/react` and `@testing-library/jest-dom`).
2.  **Styling**: The project uses **CSS Modules** or standard CSS classes (e.g., `.board`, `.row`, `.card`, `.btn-primary`). If styled-components are used, the logic remains identical but selectors change slightly. I will assume standard class-based CSS for maximum compatibility.
3.  **Viewport**: Tests will simulate a `375px` width (standard iPhone SE/Mini width).
4.  **Components**:
    *   `<Board />`: The main container.
    *   `<Row />`: Represents a list item or task row within the board.
    *   Primary Controls: Buttons for actions like "Edit", "Delete", "Move".

### Risks & Edge Cases
1.  **Global CSS Reset**: If the project uses a global reset that forces `box-sizing: border-box`, padding calculations are straightforward. If not, we must account for `content-box`. *Mitigation*: The test will check computed styles or rely on the layout wrapper to contain overflow.
2.  **Flexbox Wrapping**: If `<Row />` items are in a flex container, they might wrap unexpectedly at 375px. The "No Horizontal Scroll" test must verify `overflow-x: hidden` on the root layout or board container.
3.  **Tap Target Context**: A button might be 44px high but only 20px wide. The requirement is usually *either* dimension >= 44px, or both. I will enforce a minimum area or strict 44x44 box for primary interactive elements to be safe.
4.  **Test Isolation**: Changing `window.innerWidth` affects global state. We must mock it carefully per test case to avoid cross-test pollution.

### Implementation Strategy
1.  Create `src/__tests__/mobile-experience.test.tsx`.
2.  Mock `window.innerWidth` to `375`.
3.  Render `<Board />` with sample data.
4.  **Test 1 (Layout)**: Assert that the board does not exceed viewport width and no horizontal scrollbar is visible.
5.  **Test 2 (Tap Targets)**: Query all primary buttons/interactive elements. Assert their bounding boxes are >= 44px in height and width.
6.  **Test 3 (Row Visibility)**: Assert that `<Row />` components stack vertically or fit within the card layout without clipping content.

## 2. Exact File Edits

### File: `src/__tests__/mobile-experience.test.tsx`

```diff
+// src/__tests__/mobile-experience.test.tsx
+
+import React from 'react';
+import { render, screen } from '@testing-library/react';
+import '@testing-library/jest-dom';
+import { Board } from '../components/Board';
+import { Row } from '../components/Row';
+
+// Mock window.innerWidth for mobile simulation
+const setMockViewport = (width: number) => {
+  Object.defineProperty(window, 'innerWidth', {
+    writable: true,
+    configurable: true,
+    value: width,
+  });
+  window.dispatchEvent(new Event('resize'));
+};
+
+describe('P7-03: Mobile Experience Tests (375px)', () => {
+  const mockRows = [
+    { id: '1', title: 'Task One', status: 'todo' },
+    { id: '2', title: 'Task Two', status: 'in-progress' },
+    { id: '3', title: 'Task Three', status: 'done' },
+  ];
+
+  beforeEach(() => {
+    // Reset to desktop width before each test to ensure isolation
+    setMockViewport(1920);
+  });
+
+  describe('375px Layout Assertions', () => {
+    it('should not have horizontal scroll on the board container', () => {
+      setMockViewport(375);
+
+      render(<Board rows={mockRows} />);
+
+      // Assuming the board has a class 'board' or 'app-root' that contains content
+      const boardContainer = document.querySelector('.board') || 
+                             document.querySelector('.app-root') || 
+                             document.body;
+
+      // Check for horizontal overflow
+      expect(boardContainer).toHaveStyle({
+        'overflow-x': 'hidden',
+      });
+
+      // Assert that the container width does not exceed viewport width
+      const rect = boardContainer.getBoundingClientRect();
+      expect(rect.width).toBeLessThanOrEqual(375);
+    });
+
+    it('should stack rows vertically in a mobile card layout', () => {
+      setMockViewport(375);
+
+      render(<Board rows={mockRows} />);
+
+      const rows = screen.getAllByRole('listitem'); // Assuming Row uses role="listitem"
+      
+      expect(rows).toHaveLength(mockRows.length);
+
+      // Verify vertical stacking: each row should be below the previous one
+      // We check that no two rows overlap significantly in Y-axis
+      const rowRects = rows.map((row) => row.getBoundingClientRect());
+      
+      for (let i = 0; i < rowRects.length - 1; i++) {
+        const currentBottom = rowRects[i].bottom;
+        const nextTop = rowRects[i + 1].top;
+        
+        // Allow small margin of error (e.g., 5px) for gaps
+        expect(nextTop).toBeGreaterThan(currentBottom - 5);
+      }
+    });
+  });
+
+  describe('Tap Target Sizing (>=44px)', () => {
+    it('should enforce minimum 44x44px tap targets for primary controls', () => {
+      setMockViewport(375);
+
+      render(<Board rows={mockRows} />);
+
+      // Query all interactive elements that are likely primary controls
+      // Adjust selectors based on actual component structure (e.g., .btn, [role="button"])
+      const buttons = screen.getAllByRole('button');
+
+      buttons.forEach((button) => {
+        const rect = button.getBoundingClientRect();
+        
+        // Assert minimum dimensions for touch targets
+        expect(rect.width).toBeGreaterThanOrEqual(44);
+        expect(rect.height).toBeGreaterThanOrEqual(44);
+      });
+    });
+  });
+});
```

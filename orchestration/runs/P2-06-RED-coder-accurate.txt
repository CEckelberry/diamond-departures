### 1. Concise Plan

To satisfy the RED phase of TDD for the player detail and history endpoints, we will:

1.  **Create Test Infrastructure**: Define a `TestPlayerDetail` class in `apps/api/tests/test_players.py`.
2.  **Implement Mocks**: Create a `MockPlayerRepository` that returns specific data structures for valid IDs and raises `ValueError` (or returns empty) for invalid IDs to simulate database lookups.
3.  **Write Failing Tests**:
    *   `test_get_player_detail_success`: Asserts 200 OK, checks structure of metadata, season totals, stat line, and recent games.
    *   `test_get_player_history_success`: Asserts 200 OK, checks time-ordered points for a specific stat (e.g., 'points').
    *   `test_get_unknown_player_returns_404`: Asserts 404 for both detail and history endpoints.
    *   `test_get_history_missing_stat_returns_400`: Asserts 400 when the `stat` query parameter is missing.
    *   `test_get_history_invalid_stat_returns_400`: Asserts 400 when an invalid stat key is requested.
4.  **Ensure Failures**: Initially, these tests will fail because the endpoints do not exist or return 404/500 by default in the FastAPI app.

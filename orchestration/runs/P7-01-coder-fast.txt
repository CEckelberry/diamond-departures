# Packet P7-01 — Performance pass GREEN

## 1. Plan, Assumptions & Risks

### Assumptions
1.  **Architecture**: The application uses a React-based frontend with a WebSocket or SSE connection for real-time board updates.
2.  **State Management**: Board state is managed via a central store (e.g., Redux/Zustand) or complex props drilling.
3.  **Animation Library**: Animations are handled via `framer-motion` or CSS transitions triggered by class names/state changes.
4.  **Existing Codebase**: There is an existing `Board` component and a `useGameConnection` (or similar) hook that handles reconnection logic.
5.  **Performance Bottlenecks Identified in RED Phase**:
    *   **Reconnect Churn**: The connection handler creates new event listeners or resets the entire board state on every minor network hiccup, causing full tree re-renders.
    *   **Board Recomputation**: The `Board` component recalculates move validity or board evaluation on every render, even if the board state hasn't changed (missing `useMemo` or `React.memo`).
    *   **Animation Overhead**: Flap/row animations trigger layout thrashing because they are not GPU-accelerated or are applied to high-frequency updating elements.

### Risks & Mitigations
1.  **Risk**: Aggressive memoization might hide stale state bugs.
    *   **Mitigation**: Use `React.memo` with custom comparison functions only where necessary. Ensure `useMemo` dependencies are exhaustive.
2.  **Risk**: Reducing reconnect churn might delay recovery from actual disconnects.
    *   **Mitigation**: Implement exponential backoff with jitter for reconnection attempts, but debounce the *state reset* to avoid UI flicker during transient network blips.
3.  **Risk**: Optimizing animations might break accessibility or visual fidelity.
    *   **Mitigation**: Ensure `prefers-reduced-motion` media query is respected and fast-pathed. Test with screen readers.

### Implementation Strategy
1.  **Optimize Reconnection Logic**:
    *   Debounce reconnection attempts.
    *   Avoid full board reset on transient disconnects; instead, queue messages or mark state as "stale" without triggering a full re-render.
    *   Use `useRef` for connection instances to prevent unmount/remount cycles.
2.  **Memoize Board Components**:
    *   Wrap `Board` and `Square` components in `React.memo`.
    *   Memoize expensive computations (e.g., move generation, board evaluation) using `useMemo`.
3.  **Optimize Animations**:
    *   Use `transform` and `opacity` for animations (GPU-accelerated).
    *   Avoid animating layout properties (width, height, top, left).
    *   Implement a fast path for reduced-motion users to skip animation calculations entirely.

## 3. Verification Commands

1.  **Run Unit Tests**:
    ```bash
    npm test -- --testPathPattern="useGameConnection|Board|Square|useAnimation" --coverage
    ```
    *   **Check**: Ensure all tests pass and coverage for `useGameConnection` and `Board` remains high.

2.  **Run Integration Tests (Phase 4-6)**:
    ```bash
    npm run test:integration
    ```
    *   **Check**: Ensure no regressions in existing functionality.

3.  **Performance Audit (Lighthouse)**:
    ```bash
    npx lighthouse http://localhost:3000 --output=json --output-path=./lighthouse-report.json
    ```
    *   **Check**: Look for improvements in "Speed Index" and "Total Blocking Time". Specifically, check that the "Main Thread Work" is reduced during board updates.

4.  **Manual Reconnection Test**:
    *   Open the app in two browser tabs.
    *   In one tab, refresh the page or disconnect the network (e.g., via DevTools).
    *   **Check**: Observe the UI. It should not flicker or reset the board entirely during transient disconnects. The reconnection should be smooth and not cause excessive re-renders.

5.  **Reduced Motion Test**:
    *   Enable "Reduce Motion" in OS/browser settings.
    *   Trigger a flip animation.
    *   **Check**: The animation should be skipped or instantaneous, and the component should not perform unnecessary layout calculations.
